# Shadowsocks 吞吐与内存实测（2026-11-01）

被测提交：[`01f5683`](https://github.com/Ember-Moth/Lunaris/commit/01f5683981c7ef871ed20d819c1f4fa16a8af083)。节点由该提交的 `git archive` 快照构建，生产实现未包含压测工具修改。原始数据见[2026-11-01-macos-m5-ssplugins.json](2026-11-01-macos-m5-ssplugins.json)。

## 环境与口径

- Apple M5，10 核，16 GiB 内存；macOS 27.0.1；go version go1.27.3 darwin/arm64。电池供电，功耗设置保持原样。
- 节点、Mihomo v1.19.33 客户端和 Go 收发端为三个独立进程；全部使用回环地址。没有用 Python 承担数据收发。
- 单监听器 `run` 模式，测试 TCP 数据面。各插件使用 classic `aes-128-gcm`，另测原生 SS2022 AES-128-GCM。不是全部协议、管理面或公网性能测试。
- 每个方向测试 1 / 8 条应用流，每组预热 1 秒、测量 4 秒，重复 3 次；下表为中位数。共 **132 轮吞吐、20 轮连接内存测试，均成功**，正式采样历时约 15.9 分钟。
- 吞吐按明文实收字节计算，单位 Gbit/s（十进制）。上传使用 64 KiB 数据帧和收端计数确认，计时包含末尾排空；下载按客户端计数窗口计算。两个方向的测试路径不同。
- RSS 每约 200 ms 通过 `ps` 采样，仅统计节点进程。它不等于 Go 活跃堆，也不包含客户端、目标进程或内核 socket 缓冲；峰值是采样峰值。
- 内存测试另起新节点进程：空闲 → 32 条已认证空闲流保持 4 秒 → 关闭 3 秒 → 128 条流保持 4 秒 → 关闭 10 秒。没有强制 GC。
- kcptun 使用默认单 KCP/smux 载体、AES、FEC 10/3、smux v1；32/128 是逻辑 Shadowsocks 流数。未注入额外延迟或丢包。
- 所有进程共享本机 CPU，未隔离其他应用、未固定 CPU 频率。因此这里只作本机端到端比较，不能当作独立 Linux 服务器或公网容量上限。

## 观察

- 这组条件下，原生 classic 的 8 流下载/上传约 **24.81 / 19.02 Gbit/s**；原生 SS2022 约 **39.90 / 26.29 Gbit/s**。SS2022 下载接近本次直连对照（38.39 Gbit/s），不宜继续据此推算节点独立运行的上限。
- WSS 复用、ShadowTLS、Restls 和 KCP 的端到端成本明显不同。默认单载体 kcptun 的 8 流结果约 **0.8–0.9 Gbit/s**，没有出现接近 8 倍的扩展；这些数字只对应这里的窗口、FEC、压缩及载体配置。
- 新节点空闲 RSS 约 **17–18 MiB**；128 条已认证空闲流约 **32–61 MiB**。吞吐阶段采样 RSS 最高的是 gost WSS+smux（108.8 MiB），其次是 Restls（77.5 MiB）。
- 关闭连接后，部分进程 RSS 没有立即回落，也有明显回落的案例。RSS 保留可能包含 Go 堆、缓冲池和驻留页；本轮没有堆剖析或长时间浸泡测试，不能据此认定存在或不存在内存泄漏。
- 三轮之间存在明显波动，例如 Restls 的 8 流下载为 2.13–4.19 Gbit/s。结果反映当前主机、客户端和节点组合，不应仅凭单个峰值或局部排序判断插件的固有性能。

## 复现

本报告是 `01f5683` 的历史文件模式实测，原始数据保留不变。精确复测需要检出包含当时压测工具的 `7c0882d`，并使用 `01f5683` 快照构建的节点二进制；当前节点已移除文件模式。

当前版本的压测流程改为 JSON API 创建资产与配置，停止配置进程后，从 SQLite committed 启动独立的 managed 数据面：

```sh
go build -C test/clients/ssplugins -o ../../../bin/ssplugins-bench ./bench
make build-web
python3 scripts/bench-ssplugins.py --output docs/benchmarks/local-ssplugins.json
```

当前脚本记录 `node_mode: managed` 和 `provisioning: json-api`。新结果的启动方式和二进制构建不同，不能直接覆盖本报告。测试不修改系统代理、路由、功耗设置或生产配置。

配置细节见[插件说明](../shadowsocks-plugins.md)。本轮没有测试其他加密方法、真实 WAN/CDN、UDP/UoT 包速率、故障恢复压力或长时内存稳定性。
